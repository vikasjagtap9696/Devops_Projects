AI DATABASE ASSISTANT
COMPLETE BEGINNER-FRIENDLY PROJECT DOCUMENTATION
=================================================

VERSION / PURPOSE
-----------------
This document explains how to recreate the project represented by the supplied working
project files. It is written for a beginner and keeps the same overall flow used by the
project:

User question
   -> Frontend
   -> API Gateway
   -> Lambda
   -> RDS MySQL schema discovery
   -> Local FastAPI AI Gateway
   -> Ollama
   -> Qwen3:14b
   -> SELECT SQL
   -> Lambda SQL validation
   -> RDS query execution
   -> Frontend result

=================================================
1. WHAT THIS PROJECT DOES
=================================================

The user types a normal-language question such as:

    Show employees from Pune

The application sends the question to AWS API Gateway. API Gateway invokes Lambda.
Lambda connects to RDS MySQL, discovers the current schema from information_schema,
and sends the question plus schema to the local AI gateway.

The local AI gateway sends the prompt to Ollama running on the developer laptop.
Ollama runs Qwen3:14b with thinking disabled and returns SQL.

Lambda validates the returned SQL. The current implementation allows one SELECT
statement and blocks common write/DDL operations. Only after validation is the query
executed against RDS.

The frontend displays the generated SQL and the returned rows.

    https://ollama.com/

=================================================

Run:

    ollama pull qwen3:14b

    http://127.0.0.1:11434/api/generate

=================================================
9. UNDERSTAND ai_gateway.py
=================================================

The file ai-gateway/ai_gateway.py creates a FastAPI application.

Main endpoint:

    POST /generate-sql

The request contains:

    question
    db_schema

The application builds a prompt telling Qwen3 to return only one MySQL SELECT query.
The Ollama request uses:

    model = qwen3:14b
    think = false
    stream = false

Ollama returns the model response and the FastAPI service returns the SQL as JSON.

The local service also exposes:

    GET /

for a simple running-status response.

=================================================
13. CREATE A READ-ONLY DATABASE USER
=================================================

Do not use the RDS master/admin account from Lambda for normal application queries.
Create a dedicated read-only account.

Example MySQL statements:

    CREATE USER 'ai_reader'@'%' IDENTIFIED BY 'CHANGE_THIS_PASSWORD';

    GRANT USAGE ON *.* TO 'ai_reader'@'%';

    GRANT SELECT ON company_db.* TO 'ai_reader'@'%';

    FLUSH PRIVILEGES;

Verify grants:

    SHOW GRANTS FOR 'ai_reader'@'%';

Use a strong password. Do not write the real password into source code.

=================================================
14. CREATE RDS MYSQL
=================================================

In AWS Console open RDS.

Create a MySQL database instance.

Important values needed later:

    RDS endpoint
    port (normally 3306)
    database name
    ai_reader username
    ai_reader password

The exact RDS console labels can change over time. Follow the current AWS console.

Security group:
- Allow MySQL/TCP 3306 only from trusted sources.
- Avoid opening the database broadly to the internet.
- If Lambda is placed in a VPC, configure the required subnets/security groups.

After RDS is available, test connectivity using your own credentials.

The supplied test_rds_template.py reads credentials from environment variables and does
not contain a real password.

=================================================
15. LAMBDA SOURCE
=================================================

Open:

    lambda/lambda_function.py

The Lambda performs these steps:

1. Read the user's question.
2. Connect to RDS MySQL.
3. Query information_schema.COLUMNS.
4. Query information_schema.KEY_COLUMN_USAGE.
5. Build a schema description.
6. Send question + schema to AI_GATEWAY_URL.
7. Receive generated SQL.
8. Validate SQL.
9. Execute the validated SELECT.
10. Return JSON to API Gateway.

=================================================
16. LAMBDA SQL VALIDATION
=================================================

The current source uses sqlparse.

It checks that:

- exactly one SQL statement exists
- statement type is SELECT
- common dangerous keywords are rejected

Blocked keywords include:

    INSERT
    UPDATE
    DELETE
    DROP
    ALTER
    TRUNCATE
    CREATE
    REPLACE
    GRANT
    REVOKE

The code also limits returned rows using fetchmany(100).

IMPORTANT:
This is an application-level safety layer, not a complete SQL security system. Keep the
RDS user read-only as an additional protection.

    ai-database-assistant

=================================================
20. LAMBDA NETWORK ACCESS TO RDS
=================================================

If RDS is private, Lambda must have network access to it.

In Lambda -> Configuration -> VPC configure the required VPC, subnets and security group.

The RDS security group must allow the Lambda security group to connect on TCP 3306.

If the Lambda also needs outbound internet access to reach the Cloudflare AI gateway,
review the VPC routing/NAT design. Do not assume a private subnet has internet access
without NAT/routing.

If your working deployment uses a different network design, reproduce that design in
your own AWS account.

    cloudflared --version

    http://127.0.0.1:8000

    https://YOUR-TEMP-HOSTNAME.trycloudflare.com/generate-sql

Keep both FastAPI and cloudflared running.

31. OPTIONAL PUBLIC FRONTEND WITH S3 + CLOUDFRONT
=================================================

For a public frontend, one possible architecture is:

User Browser
    |
    v
CloudFront
    |
    v
S3 frontend files
    |
    v
API Gateway
    |
    v
Lambda

Steps at a high level:

1. Create an S3 bucket in the required region.
2. Upload frontend/index.html.
3. Keep the bucket private when using CloudFront Origin Access Control (OAC).
4. Create a CloudFront distribution.
5. Configure S3 as the origin.
6. Configure OAC so CloudFront can read the private bucket.
7. Set the default root object to index.html.
8. Configure HTTPS through CloudFront.
9. Update API Gateway CORS to allow the CloudFront origin.

Do not make the S3 bucket public just because a static website tutorial shows public
bucket policies. A CloudFront OAC design can keep the bucket private.

Official AWS documentation:

S3 website hosting:
https://docs.aws.amazon.com/AmazonS3/latest/userguide/WebsiteHosting.html

CloudFront secure static website:
https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/getting-started-secure-static-website-cloudformation-template.html

36. COMMON TROUBLESHOOTING
=================================================

PROBLEM: ollama command not found

Check Ollama installation and PATH. Restart the terminal after installation.

PROBLEM: qwen3:14b not found

Run:

    ollama pull qwen3:14b

Check:

    ollama list

PROBLEM: FastAPI cannot connect to Ollama

Check:

    http://127.0.0.1:11434

and ensure Ollama is running.

PROBLEM: FastAPI starts but Lambda cannot reach it

Check cloudflared is running and Lambda AI_GATEWAY_URL points to the current public
HTTPS hostname.

PROBLEM: Quick Tunnel URL changed

Quick Tunnel hostnames are temporary. Update Lambda AI_GATEWAY_URL and retest.

PROBLEM: Lambda cannot connect to RDS

Check:
- DB_HOST
- DB_PORT
- DB_NAME
- DB_USER
- DB_PASSWORD
- RDS security group
- Lambda VPC/subnets/routes

PROBLEM: Access denied for ai_reader

Verify the user exists and has:

    SELECT ON company_db.*

PROBLEM: Browser CORS error

Check API Gateway CORS. Ensure the frontend origin is allowed and the POST method and
content-type header are permitted. Check the browser's OPTIONS preflight request.

PROBLEM: file:// frontend gives origin null

Run the frontend through Live Server or another local HTTP server.

PROBLEM: SQL is rejected

Inspect the generated SQL. The Lambda intentionally allows one SELECT statement and
blocks several dangerous keywords.

PROBLEM: Lambda imports fail

Rebuild dependencies for the exact AWS Lambda Python runtime and Linux architecture.
Do not blindly upload Windows-specific binary wheels.
